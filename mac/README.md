# Roughcut for Mac

A SwiftUI window for the `roughcut` CLI in this repo, built as a line of steps: drop your footage, say what the video is, add the parts you want (music, sound effects, motion graphics), and send it down the line. Then **Open in Final Cut Pro**.

It runs the same Python engine you already set up (`.venv/bin/roughcut`) and reads its `--progress-json` stream. Nothing is reimplemented in Swift.

## Build and run

Set up the Python CLI first (repo README → Setup). Then, from the repo:

```bash
mac/scripts/build-app.sh --install
open /Applications/Roughcut.app
```

That builds `mac/build/Roughcut.app` and copies it to Applications. After `roughcut update` says the Mac app changed, run the same build command again.

While working on the app: `open mac/Package.swift` (opens in Xcode), pick the **Roughcut** scheme, and press Run. `swift run Roughcut` works too, but notifications need the packaged app.

Needs macOS 14+ and Xcode or the Command Line Tools (`xcode-select --install`). `swift test` runs the RoughcutKit tests and needs full Xcode for XCTest. CI builds, tests, packages and launch-checks the app on every push (`.github/workflows/ci.yml`, Xcode 16.4).

The build is signed ad hoc, so after each rebuild macOS may ask again to allow Keychain access (for your API key) and access to footage folders. To stop that, sign with your free Apple Development certificate: `ROUGHCUT_SIGN_IDENTITY="Apple Development: …" mac/scripts/build-app.sh --install` (`security find-identity -v -p codesigning` lists yours).

## First launch

1. The app looks for the CLI in this order: the path set in Settings, the repo it was built from, `~/Archer-OS/.venv/bin/roughcut` and a few other usual spots. If it can't find it, the banner at the top of the window says so. Point to it in **Settings → General**.
2. Choose who plans the edit. **Claude (your Pro/Max plan, via Claude Code)** needs Claude Code installed and signed in (in Terminal: `claude`, then sign in with your Claude account in the browser; the banner at the top clears by itself when you come back to the app, or click **Check again**). **Claude (API key)** needs a key in **Settings → API Keys** (or click **Use keys from Terminal** to import `ANTHROPIC_API_KEY` from your `~/.zshrc`). Apps opened from the Dock don't see shell variables, so keys are stored in the macOS Keychain and passed to the CLI only while it runs. Save updates a stored key in place (the old one is never deleted first, so a refused write leaves the working key), saves each of the two boxes on its own, and shows each one's result under it (Saved, No change, Removed, or why it wasn't saved); an emptied box removes that key, but not when the Keychain couldn't be read.
3. **Claude Code older than 2.1.295** (Claude (your Pro/Max plan) only) is never shown pictures, so a cut made with it has no visual log and reference pictures for the graphics aren't used. The banner at the top says so whenever a build would show it any (Visual log on, or a reference picture with motion graphics on), and **Settings → General → Setup check** has a Claude Code row with the same sentence; the fix is `claude update` in Terminal, then **Check again**. It comes from `roughcut doctor --json`'s `claude_code_pictures_note` (`DoctorReport.picturesNote(for:)`).
4. **Settings → General → Versions** says which commit the app was built from and which the engine runs (`App 3f9c2ab · Engine 3f9c2ab`; `-dirty` after one means uncommitted changes in the app's own files (`mac/Sources`, `Package.swift`, `Resources`, `scripts`), or in `roughcut/` or `pyproject.toml` for the engine; `unknown` means git couldn't say, or this isn't a checkout of its own). After `roughcut update` pulls a change to the app itself, it warns that the app may be out of date and to rebuild with `mac/scripts/build-app.sh --install`; an update that only changed the engine, or `mac/`'s README or tests, doesn't. An app run with `swift run` or Xcode has no stamp and says `unknown`. **Settings → General → Setup check** confirms ffmpeg, transcription, the graphics renderer, Claude Code and keys (this runs `roughcut doctor`). When Venture Studio is on this Mac, a Venture Studio row says what Roughcut can read from it (the catalog snapshot's date, items, folders) or why not; it never blocks a build, and there's no row without Studio. A build of footage inside a Studio library doesn't ask anything in the app: it writes to the default folder next to the footage, inside the library, and the paper edit's warnings say so (in Terminal, `roughcut build` offers a folder outside it).

## What's in the window

The window is a line of steps, like an assembly line you add parts to. A strip along the top shows the stations (done, the one you're on, still to come) with what each holds; the middle is one step; **Back** and **Next** are at the bottom, and a click on a station jumps there. A plain cut is four steps (**Footage**, **Brief**, **Add**, **Ready**); each part you add on the Add step becomes a step of its own, between Add and Ready. Which parts are on the line is read from the build's settings, so a preset that turns graphics on, or a sound folder remembered from last time, puts that part there by itself; removing a part takes what it brought out of this build (the songs, the sound sources, the graphics switch; the graphics look, logo and pictures stay remembered). The logic (`BuildFlow`, `LinePart`, `MachineLine`, `FootageCount`, `SetupChecks` in `RoughcutKit`) is tested; the views only draw it.

- **Footage**: drop folders or clips, or **Choose…** (a folder or clips handed to the app from Terminal, `open -a Roughcut FOLDER`, or from Finder's Open With, are added too, and the window goes to this step). Each source shows what is in it ("9 videos"), counted from file names the way the engine's scan reads folders (subfolders in; hidden files and library bundles out; `Fixtures/media-extensions.json` is read by a Python test too, so the two agree), a few seconds at most, off the main thread. Nothing is probed, so there is no runtime yet.
- **Brief**: **Start from** a preset (Venture OC, Save the Kid, or one you saved with `roughcut preset save`; **None** leaves the form as it is). Picking one fills the brief, length, pacing, format and graphics look; change anything after. A brief you'd already typed is kept, after the preset's. Then the brief, the length (**Auto**, 45s, 90s, 3m, 10m, or type one) and the **Feel**:
  - *Pacing*: Auto (the default) is what Claude reads in the brief while it plans (tight for tight cuts, snappy or no dead air; loose for let it breathe or slow and reflective; otherwise medium), what you typed winning over the preset's part. Without AI, plain wording rules stand in ("tight", "snappy", "punchy" cut tight; "let it breathe", "keep it loose", "slow-paced" cut loose; "don't cut it too tight" or anything else, medium). Claude plans the target length at the pacing it picks. Pick Tight, Medium or Loose to choose it yourself.
- **Add**: Music, Sound effects and Motion graphics, each with what it does and **Add** / **Added** + **Remove**. Motion graphics are designed by the AI, so with provider None the row is disabled, with a note.
- **Music**: *a song that ducks under speech and ends with the cut*: choose one, drop song files on the step, or click **Paste** after copying a song in Finder or Venture Studio (or its full path); anything that isn't a song file Roughcut reads goes nowhere, with a note. When Venture Studio is on this Mac, **From Venture Studio…** lists its audio from the catalog snapshot (search, a collection filter, favorites; read only, stopped after 30 s or with Stop) and adds your picks as plain files. A preset's Studio collection of songs (`music_from`, set with `roughcut preset save`) applies to Terminal builds only: the app builds from its form and never sends `--preset`.
- **Effects**: a folder (or single sounds) of whooshes, pops and hits for accents at section changes and graphics, plus, when Venture Studio is on this Mac, a Studio collection by name. They're remembered for the next build; a preset you saved with sound effects fills them in, and the built-in ones leave yours as they are. A collection name you type stops the build if Venture Studio has no such collection; one remembered from before, or a preset's, is only a warning in the paper edit if Studio has lost it. Re-cut keeps the cut's own sounds.
- **Graphics**: the look (a preset's, or your own words), a **Logo** and **Reference images**, and, if an earlier video's approved graphics are matched, **Don't match**.
- **Ready**: the line as it will run, each part with an **Edit** that goes back to it, a line of what Fine-tune holds, and **Build rough cut** (⌘↩) with what it costs ("Uses your Claude plan"). What stops a build (no footage, a length that isn't one, a missing song) is said at the bottom and the button waits.
- **Fine-tune** (from Ready): who plans the edit and the model (the provider, model, server URL, effort, looking at the footage and which model describes it), the project name, **Open in Final Cut Pro when it's done**, the dialogue level every clip's speech is matched to, short fades at edits, the format, **Punch-ins**, **Keep “um” and “uh”** and **Also make a dialogue-only version** (the Stringout).
  - *Punch-ins*: a 112% zoom alternating at each jump cut no B-roll covers (not on a clip letterboxed in the cut's format). Auto (the default) turns them on when Claude reads the brief asking for punch-ins at the jump cuts (not "no punch-ins" or a one-off "punch in on Roy's face"); without AI, when it says "punch-ins" or "punch in on the jump cuts". On and Off decide it yourself.
- **Recent** (in the toolbar): reopen an earlier result, show it in Finder or forget it. Whether each cut's file is still there is looked for in the background, a couple of seconds at most per file (`PathProbe`), when the app opens and whenever it is brought forward; an output folder on a network share that has stopped answering never freezes the window, and a cut is hidden only once a check has found its file gone. The same goes for the paper edit button, and for a logo, approved graphic or reference picture under `/Volumes` (not checked by the form: the CLI names one it can't read when the build starts).
- **Get ready**: when something Roughcut needs is missing and nothing has been dropped yet (ffmpeg, a speech engine, Claude Code or a key, the graphics renderer), the first screen lists what is ready and what isn't, with the command to run (and a **Copy** button) or where in Settings to go, **Skip for now**, **Use an API key instead** and **Continue without AI** where they apply. It goes away by itself once the checks pass; the thin banner at the top still says what is wrong in the steps after.

While a run goes the strip becomes the machines at work (**Listen**: find the media, read the clips, find the pauses, transcribe; **Watch**: look at frames; **Plan**; **Cut**; **Graphics**; **Export**: write the Final Cut file), the belt moves under the one that is working, and the middle says what it is doing as the pipeline reports it, with its place in the line ("Step 3 of 6") and "N of M" where it counts. A machine the run passes without using (no frames looked at, no graphics) drops off the strip. **Details** shows the log; **Cancel** stops the run. The Mac doesn't idle-sleep while a run is going. When it ends while you're in another app, the Dock icon bounces and a notification says it's ready (or why it stopped).

The result screen leads with the cut's length and **Open in Final Cut Pro**, the one thing to do next. It shows the version, the project and event to open in Final Cut (for a version after the first it also says what to choose if Final Cut asks about items with the same names: **Keep Both**, since each version is its own project), how many graphics made it, and, when fewer are on the timeline than were planned, the note that says why (it wraps under the count), and, under **More about this cut**, how many clips were looked at, what the AI cost, and anything left out. **Show in Finder**, **Read the edit notes** (the paper edit) and the warnings are below it, and **New Cut** in the toolbar goes back to the line with the footage and brief kept. After a revision or a re-cut, a **What changed in this version** box under that lists what differs from the version before: length, lines, sections, B-roll, graphics (kept, redesigned, new, removed), pacing, punch-ins, format, sound effects, music, spellings. When nothing a viewer would see changed (a re-cut at the same settings, or notes that only touched how the graphics look), the first line says so in a highlighted style and what to try instead. It also lists a graphic that was meant to be made and never came back, so it never claims more than the cut has. From there:

- **Not quite right? Adjust…** opens two choices. **Quick change** (the old Re-cut) runs `roughcut render`: the same plan at a different pace or format, or with punch-ins on or off, with no model call.
- **Finish graphics**, next to the Graphics line, runs `roughcut render <folder> --design-missing`: it makes the graphics a cut still waits for, without planning the cut again, and the result is a new version like a re-cut's (same stages, Cancel and errors). It shows only where something is left to make: graphics that were never designed (the usage limit, a failed request), graphics that kept an earlier look or clip because the new design or render didn't come back (the Graphics line's note says "N keep their earlier look/clip"), a render that failed, or a version written before its graphics were made. A graphic the cut has no room for is not one of them, so a finished cut never shows the button. The caption under it says what it will do for this version (design the graphics a cut was written without; design the new look for those still in their earlier look; try again to design and render those that didn't come back). It asks the model that planned the cut for the missing designs (with the saved notes and reference pictures; with only pictures or the Redesign switch and no notes, from the pictures, not the earlier look), so it needs your plan or key like a build does. It sends no other setting, except `--no-stringout` for a cut that has no Stringout project (a revision writes only the Rough Cut), so the event's project list is the same from one version to the next. While the usage limit is still on and no design comes back, nothing is written (a copy of the last version would only pile up): the window stays on the cut and says to wait for the reset. When a try changed nothing (the model was busy, a render failed again) the button reads **Try again** and says each try is a version of its own.
- **Ask Claude** (the old Revise) runs `roughcut revise`: Claude re-plans from your notes as the next version, and the earlier cut stays in `history/`. With graphics in the cut, it also has **Reference images** (its own list) and **Design the graphics again**, below. A cut that fell back to the stringout has only Quick change.

If a run stops after the plan was saved, the error offers **Finish without AI**. If your Claude plan's limit or your API credit ran out before anything was written, it says nothing is lost: build again (or revise again) after the reset.

**A revision, re-cut or Finish graphics that stops** (a usage limit, Cancel, an error, a crash) reads the folder's `result.json` afterwards. A revision with graphics writes its cut without them first, as the newest version (the cut you started from stays where it was), so a stop leaves a version 2 you could open. If the folder holds a newer version than the cut you were on, the window shows that version instead of going back, with a banner: "Version 2 was written, but its graphics weren't finished: <why>. Your earlier version, Trip v1.fcpxml, is still there." (A cut an earlier run left is not blamed on this one: the app notes which version the folder held when the run began, and only a newer one counts. The engine's own file name and Terminal command are left out of <why>.) Open in Final Cut, Show in Finder and Paper Edit then act on that newer file, **Finish graphics** is next to the Graphics line, and the advice under the banner says so (after a usage limit: click it once your plan resets; after Cancel: click it to make them from the saved plan). After a usage limit while graphics are designed, the version keeps every graphic's earlier look and the banner says so ("Version 2 was written with 2 graphics in their earlier look: <why>."; the Graphics line's note too), and Finish graphics designs the new look after the reset. The banner's **Finish without AI**, when it shows beside Finish graphics, says it adds only the graphics whose designs were saved and calls no model. The Revise box keeps your notes after a stopped revision wrote its version, because they are in that version, and clears them when that version is finished (Finish graphics, Finish without AI), as a finished revision does. When nothing newer was written (a limit during planning, say), the window goes back to the cut you were on with your notes still in the box, and a limit says "Click Revise again after your plan resets". A build that stopped after writing its cut (a limit while the graphics were designed) shows that cut the same way. The newer version is added to Recent rough cuts. Not covered: quitting the app mid-run and opening an older entry from Recent rough cuts later; open the newest file in the folder from Finder, or run `roughcut render <folder> --design-missing` in Terminal.

**Roughcut → Update Roughcut…** runs `roughcut update` and shows what changed.

## How it's put together

| | |
|---|---|
| `Sources/RoughcutKit/` | Foundation-only core: `BuildOptions` (form → CLI arguments; saved settings that survive app updates), `Revisions.swift` (`Preset`, `ReviseOptions` with its reference pictures, `RedesignSwitch` for the Redesign the graphics toggle, reading the `resume` command), `ReferenceImages` (which files a reference list takes, the 8 limit, `--graphics-ref` arguments, where pasted bitmaps are kept and when they go), `RunState` (where the window goes when a run ends), `StoppedRun.swift` (reading the folder's `result.json` after a stop, bounded, whether it holds a version newer than the cut and than the folder's version when the run began, the banner and advice for it, and when Finish graphics is offered and what it says), `StoppedRevision` in `RunState.swift` (which folder's Revise box still holds a stopped revision's notes), `ProgressEvent`/`RunResult` (JSON-lines decoding, run summary, and `RunChanges`: what a revision or re-cut changed, from the done event's `changes`; `DoctorReport` with its optional `StudioStatus`), `CLIProcess` (runs the CLI and streams its output, never dropping the final `done` event; `collect(timeout:)` for short commands), `StudioMusic.swift` (`StudioSong` from `roughcut studio music --json`, the sheet's filter, `MusicFiles`: what the Music bed accepts), `CLILocator` (finds the CLI, fixes PATH for Homebrew)., `Credentials.swift` (`KeyAccount`, the `KeyStore` protocol, `KeyForm`: the API Keys tab's per-account saves, tested with a fake store), `VersionStamp.swift` (`AppStamp` from Info.plist, `VersionStamp`: the Versions row and its warning), `BuildLine.swift` (`BuildFlow`: the steps and the parts on the line read from the options, moving along them, what each station and footer says), `RunLine.swift` (`Machine`/`MachineLine`: the pipeline's nine stages as six machines), `Footage.swift` (`MediaKind`, `FootageCount`: what a source holds, counted from file names the way the engine's scan reads them), `SetupChecks.swift` (the Get ready page's rows from the doctor report). The build form's rules are here too, so the view only calls them and they are tested: `BuildOptions.choose(provider:)`, `setGraphics`, `settle()`, and `TimeText`. Unit-tested. |
| `Sources/Roughcut/` | The SwiftUI app: `AppModel` (state machine: the line of steps → running → finished/failed; build, re-cut, revise and finish graphics; presets; recent runs; footage counts; keep-awake and notifications; update), `ContentView` (which screen, the toolbar's Recent menu and New Cut, the setup banner), `FlowView` (the strip, the step, Back/Next, the notice over a stopped build), the steps (`FootageStep`, `BriefStep`, `PartSteps`: Add, Music, Effects, Graphics; `ReadyStep`: Ready and Fine-tune), `LineStrip` and `LineTheme` (the belt and stations; the one amber accent on the system's colors; the button styles), `GetReadyView`, `StudioMusicSheet` (songs from Venture Studio), `ReferenceImagesView` (the reference pictures list: thumbnails, Add, Paste, ⌘V, drop) and `ReferenceFiles` (pasteboard, drops and thumbnails; AppKit), `RunView` (the machines at work and the log), `ResultView` (the finished cut: open in FCP, Finder, the edit notes, the What changed box; Adjust: re-cut and revise), `UIPreview` (opens the app at any screen with made-up content, for the pictures below), `SettingsView` (General: the CLI, Versions, Setup check; API Keys), `Keychain` (the Security-backed `KeyStore`). |
| `Tests/RoughcutKitTests/Fixtures/` | Real CLI output: `progress-sample.jsonl` (a build), `progress-revise-sample.jsonl` (a revision, with its `changes`), `progress-stopped-revise-sample.jsonl` and `progress-limit-revise-sample.jsonl` (an `error` event with `written`: a crash after the cut without graphics, and the usage limit after a version was written), `progress-pending-revise-sample.jsonl` (a `done` whose `graphics` has `pending`), and `result-partial-revise-sample.json` / `result-pending-revise-sample.json` (the `result.json` those runs left). and `doctor-sample.json` (the keys of `roughcut doctor --json --offline` with placeholder values). `tests/test_progress.py` in the Python suite fails if the CLI's output (or, for doctor, its keys) drifts from them. |
| `Tests/RoughcutKitTests/Fixtures/target-lengths.json` | The lengths the Target length field and `--target` must take and refuse. Read by `FormStateTests` and by `tests/test_timecode.py`, so the two parsers can't drift. |
| `scripts/build-app.sh` | Packages the SwiftPM executable as a signed (ad-hoc) `.app` with an icon. It also records this repo's CLI path and the commit it was built from (`RoughcutAppCommit`, `RoughcutAppSourceCommit`: the app's own files only, `unknown` when git can't say) in `Info.plist`. |

**Re-cut** in the result screen runs `roughcut render`: the same plan at a different pace or format, with no model call. Format starts at **Same as this cut**, so a vertical cut stays vertical; pick **Match footage** to go back to the footage's own shape. **Punch-ins** also starts at **Same as this cut** (it says whether the cut has them); On or Off changes them, e.g. when Auto read the brief differently from what you meant. Revise notes can change them too ("make it looser", "remove the punch-ins"): the new version takes the pacing and punch-ins Claude reads in the notes, and the paper edit's revision block says so. Only the new notes count, so a Re-cut you made since stays unless they ask to change it. Keep um/uh and the Stringout stay as the cut has them (the build form's toggles are for the next build). **Finish without AI** runs `roughcut render <folder>` with the run's own settings, as the CLI's hint says.

**Revise** re-plans the cut from your notes. A cut made without AI (provider None) has no planner to reuse, so the box asks which one re-plans it: Claude through your plan (Claude Code) or your API key, or the form's OpenAI/Ollama model. If a revision or re-cut stops (plan limit, error, Cancel), the window goes back to the cut with your notes still in the box and says what happened, or, when the run had already written a newer version, shows that version with the notes still in the box (see above); **Finish without AI** appears there when the new plan was saved. The engine keeps the cut you were on at the top level of the folder when a revision stops after writing its own cut without graphics (that partial version is the newest and `result.json` says `partial`), and a usage limit during a redesign writes the new version with the graphics' earlier look (`graphics` has a `pending` count and a note). The app reads both from `result.json` and the `error` event's `written`, and **Finish graphics** makes the rest.

**Reference images** (the build form, with motion graphics on, and the Revise box) show the graphics designer the look you want: screenshots, other videos' titles, brand sheets. Roughcut matches their style, not their content. **Add…** picks picture files, **Paste** takes a copied screenshot, image or picture files (⌘V does the same while the box is selected: click it), and you can drop pictures on the box. Each shows as a thumbnail with a remove button; at most 8 (a ninth says why it wasn't added), and anything that isn't a picture is left out with a short note. A pasted or dropped bitmap is saved as it came (a copied screenshot's TIFF as a PNG; a JPEG stays a JPEG) in `~/Library/Application Support/Roughcut/References/`, and one nothing in the saved list uses is removed after 30 days (checked at launch); a paste or drop into a full list is refused with a note before anything is saved, a bitmap over 40 MB is refused with a note, and pasting the same screenshot twice adds it once. The build form's list is remembered by path between launches (a file that has gone isn't restored) and is sent as `--graphics-ref` only with graphics on. The pictures are private, but they are sent to the AI model that designs your graphics (Claude through your plan or API key, or the model you chose), like clip frames are, and nowhere else: the app passes their paths to the CLI, which stores a reduced copy with the project and lists just the file names in the paper edit.

**Redesign the graphics** (in Revise, shown when the cut has graphics) is off until you add a picture, then turns on by itself (and off again if you remove the last picture without touching it); it sends `--redesign-graphics`, so every graphic is designed again with your notes as the direction. **That replaces every graphic, hand-edited designs included**; the earlier designs stay in the version history (`history/`). With it off, a graphic is designed again only when its own text changed or Claude reads your notes as asking for another look ("make the lower thirds bolder"). Revise starts with notes or pictures; the switch alone isn't enough, since it only changes what they do. With pictures and no notes, the cut itself is not re-planned. The Revise box's list starts empty: without new pictures, the ones the cut already has are used again, and adding pictures replaces them. Notes, pictures and the switch clear after a successful revision and stay in the box if it stops or is cancelled. A cut made with graphics off shows no pictures list, since they would be left out.

**A Mac with no saved settings** starts on the Claude API key. When Claude Code is installed and signed in with your plan and no API key works, the first launch plans through Claude Code instead (`SetupChecks.firstRunPlanner`), so the Get ready page doesn't ask for a key you don't have; settings saved before are never changed.

**Motion graphics need an AI provider.** Motion graphics are designed by the AI, so choosing **None** as who plans the edit turns the Motion graphics switch off (and disables it, with a note), and a preset with graphics on, or preferences saved before this, can't leave it on: the form never holds both. The graphics style, logo, approved designs and reference pictures are kept (hidden, and not sent) for when you pick a provider again and turn graphics back on. **Target length** (and Revise's **New length**) takes a second to 24 hours: `90s`, `8m`, `1h30m`, `8:30`, `1:02:05`. Signs, `nan`/`inf`/`1e3`, other scripts' digits, a stray colon (`::`, `1:2:3:4`) and anything over a day show "should look like 8m, 90s or 8:30 (1 second to 24 hours)" and are never sent (nor is anything over 64 characters).

**Presets**: the picked preset is remembered across launches and filled in again from the preset as it is now (brief, length, pacing, format and graphics look). A format or length saved in Terminal (`--format 1080x1920@29.97`, `--target "90 sec"`) carries over as written. If an approved graphic or logo has gone since, the form says so before you build.

**Pictures of each screen.** `ROUGHCUT_UI_PREVIEW=<screen>` (`getready`, `footage-empty`, `footage`, `brief`, `add`, `music`, `effects`, `graphics`, `ready`, `ready-problem`, `failed`, `finetune`, `running-listen`, `running`, `done`, `done-stopped`, `adjust`) opens the app at that screen with made-up content (no file, key or account of yours is read), and `ROUGHCUT_UI_APPEARANCE=dark` takes the dark look. The "Mac UI pictures" workflow (`.github/workflows/mac-ui-previews.yml`, by hand or on a push to `ui/assembly-line` that changes the app) packages the app on an Apple Silicon runner, takes a picture of each screen in light and dark (`.github/scripts/ui-previews.sh`) and puts them on the `ui-previews` branch, replaced each time, so the design can be checked against the real thing.

**The packaged app, driven end to end.** The "Mac app end to end" workflow (`.github/workflows/mac-app-e2e.yml`, by hand or on a push to `ui/assembly-line` that changes the app or the engine) packages the app on an Apple Silicon runner, installs the engine where the app looks for it (`.venv/bin/roughcut`, with mlx-whisper, so the setup check passes) and drives the window with real mouse clicks through its Accessibility tree (`.github/scripts/ui-drive.swift`, run by `.github/scripts/app-e2e.sh`): the first launch with nothing signed in (the Get ready page, **Continue without AI**), footage handed to the app with `open -a`, Footage > Brief (the Venture OC preset) > Add > Ready, Fine-tune (scrolled to, a setting ticked), a build with no AI through the app's own process runner on made-up footage (macOS `say` and ffmpeg, a transcript beside it so no speech model is downloaded), the finished cut (both versions checked against Apple's DTD, and the preset's pacing and the ticked setting read back from `result.json`), Adjust > Quick change > Re-cut (version 2, version 1 in `history/`), a run **Cancel** stops, a run that ends on a usage limit (for those two a stand-in for the command-line tool speaks the progress protocol), a fresh launch that opens the cut from the toolbar's **Recent** menu, the AI path with a stand-in for Claude Code (`.github/scripts/fake-claude.py`, installed where the engine looks for `claude`, answers the engine's real requests from the prompt): a Mac with no saved settings plans through Claude Code without a stop at the Get ready page, the **Finish graphics**, which makes both once the limit lifts), and Venture Studio's music through the app: a made-up Studio folder (`.github/scripts/fake-studio.py`, built with the tests' own fake-Studio helper), the app started with `ROUGHCUT_STUDIO_DIR` pointing at it and the footage handed over as it starts, the **From Venture Studio…** sheet, a song chosen in it with a real click, and the cut that uses the song (checked in its FCPXML) and the paper edit's Venture Studio section. The driver says in its log how many of its presses were real clicks and how many had to go through Accessibility instead (a press whose click changed nothing on screen is repeated that way). A picture and the Accessibility tree of each step go on the `ui-e2e` branch, replaced each time. What it does not cover: the real Claude (a stand-in answers, so what Claude would decide is not tested), sound effects, a real Venture Studio (a runner has none: the folder is made up), dragging files onto the window, and anything about Final Cut itself. The runner's Dock is set to hide first: on its 1024 by 768 screen the Dock covers the footer's buttons and a click there would reach the Dock.
