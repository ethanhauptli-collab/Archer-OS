# roughcut: notes for Claude Code

Footage folder → transcripts → LLM edit plan → frame-accurate timeline → FCPXML for Final Cut Pro. A Python CLI (the engine) plus a SwiftUI Mac app in `mac/` that drives it. The owner edits Venture Orange County promos and a personal YouTube channel (Save the Kid) in Final Cut Pro 11 on an Apple Silicon Mac; this tool produces the first pass they refine there.

## Invariants: don't break these

- **The model never produces timestamps for speech.** It picks segment IDs and names words; `timeline.py` computes cuts. Anything the model returns goes through `plan.normalize()`, which drops unknown IDs with a warning and never raises. No line plays twice: a repeat from another read or export is dropped and recorded as an alternate, and a take the plan's own `alternates` list among a line's others is dropped when the chosen take is in the cut, else replaced by it (heuristic/stringout plans are exempt so `render` reproduces them). Only a real retake counts (`duplicates.another_read`: at least half the line's content words, however reworded, the same line, or one inside the other): a flub or another line listed there is left where it is and never named as an alternate. The editor wins: a take `--keep` names is never dropped or replaced (when it names two takes of one line, the chosen one plays and the other stays an alternate, with a warning, and `enforce` doesn't call it missing), an avoided chosen take never goes in place of another (the other take in the cut plays and becomes chosen), and a revision that plays another take where the last version played the chosen one keeps the swap; `revise` saves the reconciled alternates in `plan.json`'s raw plan so re-cuts play the same takes, and `render` and `revise` read an older plan.json's raw alternates as its saved plan played them (`plan.as_played`).
- **No floats in FCPXML.** All times are `Fraction`s; spine `offset`/`duration` are whole multiples of the sequence `frameDuration`; source in-points snap to the source's own frame grid; audio fades are whole samples.
- **FCPXML coordinates:** spine `offset` = timeline time. Spine `start` = asset timecode origin + source in. Connected clips, markers and volume keyframes live in the **parent's (or the clip's own) source time** (`start + (frame − offset) × frameDuration`). Stills use `<video>` with a `3600s` origin; browser stills are `<clip><video duration="0s"/></clip>`. Audio-only clips carry `format` = `FFVideoFormatRateUndefined`. Every clip names its own `format` when it differs from what it would inherit (the sequence's on the spine, the parent's when connected; browser clips always), and a clip at another frame rate gets `<conform-rate scaleEnabled="0" srcFrameRate=…/>` so it plays at real speed, as Final Cut writes them. Never put `adjust-volume` on `<video>`. All of this is checked against Apple's DTD and against real Final Cut 10.7/11 exports in `tests/fixtures/fcp_exports/` (`tests/test_fcp_exports.py`; `check_invariants` enforces the format rule).
- Tests validate every generated FCPXML against `tests/fixtures/FCPXMLv1_10.dtd` (Apple's DTD) and check timing invariants (`tests/test_end_to_end.py::check_invariants`). Keep both passing.
- **The app ↔ CLI contract is `--progress-json`** (one JSON object per stdout line: `stage` / `log` / `done` / `error`; stages `scan probe silence transcribe vision plan cut graphics write`, only ever moving forward; `error` is last and may carry `resume` (after a saved plan, also on SIGTERM/SIGHUP and unexpected errors) and `kind` (`usage_limit`, `cancelled`)), `done.result` = `pipeline.result_summary` (keys may be added, never removed or renamed; `cut` holds the version's style, format, fillers and stringout so the app's Re-cut starts from them), `roughcut doctor --json` (add-only; `commit` and `app_source_commit` came after the first release, decoded as optional in Swift) and `roughcut preset list --json`. Added since, add-only and optional for the app: `done.result.graphics.pending` (graphics standing on an earlier version's design or clip; only present when above 0) and the `error` event's `written` (`{version, fcpxml, project, partial}`: the partial cut an interrupted run left as the newest version, or, after a usage limit during graphics, the version it wrote with `design_missing: true`; absent when nothing was written). `mac/Tests/RoughcutKitTests/Fixtures/progress-sample.jsonl` (a build) and `progress-revise-sample.jsonl` (a revision, with its `changes`) are real output; the Swift tests decode them and `tests/test_progress.py` fails if the Python side drifts. `doctor-sample.json` has the keys of `doctor --json --offline` checked against live output, with placeholder values (commits, paths). `progress-stopped-revise-sample.jsonl` (an `error` with `written`), `progress-limit-revise-sample.jsonl` (the same after a usage limit, `written.design_missing`), `progress-pending-revise-sample.jsonl` (a `done` whose `graphics` has `pending`) and `result-partial-revise-sample.json` / `result-pending-revise-sample.json` (the `result.json` those runs left: `partial` is there and never in a `done` event) are real too, checked by `tests/test_progress.py` and decoded by the Swift tests. Change both sides together and regenerate the fixture.
- **The app shows what a stopped run wrote, and finishes graphics.** After a revise, re-cut or Finish graphics stops (usage limit, Cancel, an error, a crash), `AppModel` reads `<folder>/result.json` (`SavedResult.read(in:timeout:)`: off the main thread and given up after 3 s, because the share the folder is on is often why the run stopped and the window never waits on it). A version numbered higher than the cut the run started from **and than the version `result.json` held when the run began** (`runBaseline`, read before the CLI starts: a partial cut an earlier run left beside the cut on screen is not blamed on a run that wrote nothing) is shown instead of going back to it (`StoppedRun.newest`, `RunEnding.wroteAndStopped`), with a banner that says it was written, why the run stopped (the engine's own file name and Terminal command left out of the reason, since the button does that) and where the earlier version is, by file name for a partial cut: "Version 2 was written, but its graphics weren't finished: <why>. Your earlier version, Trip v1.fcpxml, is still there.", or, when a usage limit left every graphic in its earlier look, "Version 2 was written with 2 graphics in their earlier look: <why>." A stopped build has no cut to compare with, so only a version the `error` event's `written` names counts (the folder may hold an earlier run's `result.json`). When `written` names a newer version `result.json` can't show (unreadable in time, or still the older one), the window goes back to the cut and says where that version's file is. Open in Final Cut, Show in Finder and Paper Edit then act on that version's file, and it joins Recent rough cuts. Nothing newer: back to the source cut with the notes kept, as before; a usage limit that wrote nothing keeps "Revise again after your plan resets" (and, for Finish graphics, "click Finish graphics again"; the engine's Terminal command is left out). After a revision stopped with its version written, the Revise box keeps its notes (they are in that version) until the version is finished (Finish graphics or Finish without AI on that folder: `StoppedRevision`), then clears as a finished revision does, so the next Revise doesn't apply them again. **Finish graphics** (`RunResult.canFinishGraphics`) shows only when graphics are planned and the version is `partial`, or `graphics.pending` > 0, or `graphics.placed` > `graphics.rendered`; a graphic the cut has no room for (planned above placed) never counts, so a finished cut or one where nothing fits has no button (`tests/test_unfinished_graphics.py` runs the engine through each case against the same rule). Its caption says what it will do by cause (a cut written before its graphics, graphics in an earlier look, graphics that didn't render); after a Finish graphics run that changed nothing and left graphics to finish the same button reads **Try again** and says each try is a version of its own. The banner's **Finish without AI** says it adds only the graphics whose designs were saved and calls no model; Finish graphics also designs the rest. Finish graphics sends `render FOLDER --design-missing` and nothing else, so the cut's settings, the model, the notes and the reference pictures come from the saved run, plus `--no-stringout` for a cut that has no Stringout project (a revision's): the project list stays the same from one version to the next, and the list of changes says nothing about it. The Graphics row shows the engine's note without its Terminal commands (`GraphicsSummary.displayNote`); the warnings keep them.
- **A rejected API key or a used-up plan/credit stops the run** (`ProviderAuthError`, `ProviderLimitError`): `build` calls `provider.verify()` before any analysis, and both are fatal during vision/planning. Only other model failures may fall back to the stringout, and that fallback is announced at the top of the report and in the CLI output.
- **The plan is saved before anything that can still fail** (cutting, graphics): `analysis.json` + `plan.json` (with `analysis_digest` and the run's settings) are written right after planning, so `roughcut render` can always finish without the model. `render` refuses a plan whose digest doesn't match, and takes every cut setting it isn't given from the saved run (in Terminal and from the app alike). `revise` writes `graphics.json` (carried designs, new ones without html) as soon as its plan is saved; `render --design-missing` designs only graphics without html, with the run's own model, never re-planning. Outputs are numbered versions written atomically (temp file + rename); earlier versions are copied to `history/` (last 5). Never move files at run start, and never delete a rendered graphics clip any written version used: Final Cut reads imported media in place. **An interim cut** (a version with graphics writes its cut without them first, `partial` in `versions.json` and `result.json`, and a headline warning "This cut is partial") is the newest version but takes nothing off the top level: only a version's final write moves the earlier cuts to `history/` and prunes, so a run that stops (usage limit, Cancel, a crash, the Mac sleeping) leaves the cut before it where it was and `render` / `render --design-missing` (a new version) tidies the top level as before. `pipeline.partial_cut` (the error event's `written`) falls back to `versions.json` when `result.json` is older than the newest version (a stop between the interim write and its `result.json`). `render --design-missing` writes no version when it can't make one worth having: the usage limit is still on and no design came back (a copy of the last version; the error says nothing was written and what to run), or no renderer is available (a version without the graphics the one before had).
- **A cut made again says when its footage is no longer what was read, and a folder has one writer.** `render` and `revise` reuse analysis.json, so `pipeline.changed_media` compares each footage file a cut uses with the fingerprint saved for it (path, size, modification time: the cache's own key) and puts one warning in the report and the log naming up to three files ("have changed since Roughcut read them ... Build the footage again"); a file that is gone is `missing_media`'s, a build (which has just read the files) doesn't ask, sounds and Studio songs have their own checks, and every stat runs under `FOOTAGE_CHECK_SECONDS` (a drive that doesn't answer is said once, the rest are not waited on). Not built, on purpose: a hash of analysis.json in plan.json (the digest already refuses a plan made for other clips, and the two files are written a few milliseconds apart).
- **Dead air is cut by the silence map, not by word times.** mlx-whisper's word times are contiguous, and the word next to a pause is stretched over it. `timeline._cut_silences` runs after merging and removes every silence longer than the style's `max_gap` (or `max(1 s, 2×max_gap)` for a finished promo over a music bed, `Clip.bed == "music"`) that has sound on both sides inside a kept piece. It never cuts a "silence" that holds a whole transcribed word. A pause split by a quiet breath or click (≤ 0.4 s, ≥ 12 dB under the speech, no word starting in it and no word whose only sound is in it, `pauses.word_in_pause`) counts as one pause: on camera it goes in one edit, breath included (the one bounded exception to "never removes sound"); in narration the breath stays. Words are dropped as Whisper inventions only by the standard −35 dB map, never by a raised one (in a noisy room, by the clip's own loudness: below). `tests/test_dead_air.py` covers the 10-14 s gap case and music-bed promos. **A cut's room is measured from where the silence map says the sound begins or stops, not from the transcript's guess** (`timeline._Spans.onset_before` / `release_after` in `speech_pieces`): when a silence ends no more than `pad_in` + `EDGE_SLACK` (0.20 s) before a kept run's first word, or begins no more than `END_REACH` (0.80 s) after its last, and no neighbouring word's sound (a cut-out filler's included) lies in between, the word's edge moves to that boundary and the padding goes beyond it (a full `pad_in` before the sound begins, a full `pad_out` after it stops), so the cut is outside the word however the transcript is off, and room tone is the same at every phrase end (`tests/test_cut_edges.py`, which fails with the guard off). Real Whisper word ends run early (a median 80 to 170 ms, 0.2 to 0.46 s at the 99th percentile; starts are mostly right, a median error of 26 to 36 ms). **A word that ended early doesn't make a pause** (`timeline.FAKE_GAP`, 0.45 s, in `speech_pieces` and `_merge`): the next word follows at once and the transcript shows a gap that is not there, and at tight pacing the run of words was split through the sound between them. On a clip whose silence map finds its pauses (`_ClipIndex.shows_pauses`: at least two silences, at least 3% of the clip quiet, as `analyze.pause_warning` asks), a transcript gap longer than the style's `max_gap` by no more than `FAKE_GAP`, with no silence on the map in it (`_Spans.overlap` under half of `max_gap`, `pause_between` not longer than `max_gap`) and no cut-out filler between the two words, is not a pause, whether the two words are in one sentence (`speech_pieces` doesn't split the run) or in neighbouring ones (`_merge` joins the pieces, `_sound_runs_through`); a clip whose map finds no pauses (loud noise: the silence level can't sit between the background and the speech) keeps deciding by the transcript, with only the bias allowed for (`EARLY_END` 0.15 s: a gap that much longer than the style's pause is not one). Measured with `.github/scripts/whisper_timing.py` (macOS `say` speech over a noise bed, transcribed by mlx-whisper large-v3-turbo, cut by `build --provider none`, judged by the audio; its own workflow, "Whisper timing", keeps the speech and Whisper's transcript between runs and compares settings on the same transcripts): tight pacing, four clips of 3 to 12 minutes (1,973 words): words whole 91.6% before this and 98.6% now, cut edges inside speech 8.8% and 0.5%, a word's edge thrown away 8.8% and 0.8%, and 3.3% more kept (243.8 s against 236.1: the sound the old cuts were cutting through); medium 99.4% and 99.8%, 2.1% more kept. The gap rule is most of it (92.6% without it, 98.5% at a 0.30 s range, 98.6% at 0.45 and 0.60); the reach (0.6, 0.8, 1.0 s) and a start slack of 0.2 s change almost nothing on these clips; a longer `pad_out` of 0.16 s buys 0.4 points for 0.9% more kept. What is left is words Whisper missed or put far from where they are (a start 0.9 s early). A person reading (public domain, the same pipeline, judged by the audio alone): 2 of 136 tight cut edges start inside speech, none of 80 medium; that check cannot tell a cut that is right from one that is too loose, so it shows only that real human speech goes through with nothing worse. **Four people reading** (the first and the most downloaded LibriVox items by three authors; the Whisper timing run's `READINGS`, four minutes each, different rooms: quietest tenth -35, -48, -58 and -48 dBFS) show what the synthetic clips can't: with `hallucination_silence_threshold` set, mlx-whisper left holes of about 2 s with speech in them in one transcript (after a token it joined with an em dash: 'fry—but', 'garden—a'), which the cut removed as dead air, 9 of 503 tight edits (6 of 283 medium) going through a sound and one 430 ms and one 500 ms long; transcribed in four ways (`whisper_variants.py`, the Whisper variants workflow) the clips had no holes without that setting (2.5 s of sound with no word near it in 1,213 s, against 7.8 s), kept the verbatim conditioning (not conditioned: the noisy clip's words lining up fell from 85% to 78% and more words appeared in pauses) and lost nothing (synthetic clips line up 90.8% against 88.5% on one, equal on the rest). So `Transcriber._mlx` no longer sets it (the silence map and the loudness map drop what Whisper still writes over silence), and `EDGE_SLACK` is 0.20 s (a soft first consonant that began 0.21 s before Whisper's start). Measured again on fresh transcripts of the same clips: the synthetic seven, tight 98.1% of words whole and 1.4% of cut edges inside speech, medium 99.5% and 1.7%; the four readings by `roughcut check`, 2 of 499 tight edits and 1 of 279 medium through a sound with the old 0.10 s slack, 1 and 0 with 0.20 s (the longest medium pause 0.85 s against 0.68 s), no pause over a second. **A noisy room's pauses and invented words come from the clip's own loudness** (`ffmpeg_ops.level_silences` over `window_rms`, 10 ms readings high-passed at 250 Hz twice so a room's rumble or hum doesn't hide a quiet word, cached as whole dB in `levels10-v2.json`, a read that failed is not cached; only for a clip whose `noise_threshold` raised the silence level above −35 dB (`>`: a quiet recording, whose level is lowered, has no room to read and its words are judged by its own lowered map, not the −35 dB one), so a clean recording is cut as before and costs no extra pass). The room is the quietest tenth of the readings, a pause is a stretch of at least 0.35 s under the room plus 3 to 6 dB (more as the speech gets louder over it), and a click (a rise of at most 50 ms that stays under the room plus 14 dB) inside a pause doesn't end it: silencedetect compares single samples with its level, so one click ends a silence and starts the next at the same moment, and a noisy room's peaks cut a pause to pieces. A clip whose speech is within 12 dB of the room has no such map. The room is found at the silence step (`_by_level`) but put to use only once the words can be checked against it (`_use_room`, in the transcript loop): the transcript's own words must stand clearly above the room (the median reading inside them at least 12 dB over the floor: `segments.speech_stands_above_room`; a horn or a laugh that is the loudest twentieth of a clip says nothing about its talker), else the loudness map is not used and every word is kept (said in the log). Used, it stands in as the clip's silences only where silencedetect's finds almost none (`analyze.shows_pauses` false: a windy shoot, a level set above the speech), and the level silencedetect ran at (`silence_db`) stays. A word is dropped as made up (`segments.split_invented_words`, said in the log) only if it lies fully inside one of the loudness pauses (±50 ms) and its own readings (their 90th percentile) are under the pause level: a raised level can sit above a quiet real word and never deletes words, a short soft word ("a", "I") that the click rule closed a pause over stays, but nothing in the clip's own loudness sits over a verse number Whisper wrote into room tone that the reader never said, which is what each of the real reading's five pauses over a second turned out to be: the cut kept the "word" and the dead air around it. A word stretched over a pause, whose speech sounds at its start, is not inside one. A clip whose pauses are too short to tell music from a room (`pause_flatness` None) is not called a room. `timeline._join_close` puts silences less than 40 ms apart together (a click ended one and began the next), because `_cut_silences` judged each half alone and never cut the second half of a pause when the piece already began where the first half ended (`tests/test_level_map.py`), but not across a word that sounds in the gap (`pauses.word_in_pause`: a soft "I" is not a click). The transcript cache key of mlx-whisper carries how it was asked (`-w2`, `transcribe.MLX_ASKED`): footage transcribed before `hallucination_silence_threshold` was dropped is transcribed again, not served from a cache that holds 2 s holes. `tests/test_level_map_review.py` has the cases an independent review built (a talker close to the room with a horn in the clip, a short soft word, rumble and hum, a quiet recording, old transcripts). Measured by the Whisper timing workflow on the same transcripts: the real reading's tight cut leaves a longest pause of 0.51 s where it left 1.01 s (none over a second, one before), 194 s kept against 204 s, 0.7% of cut edges inside speech against 1.5%; its medium cut 0.68 s against 1.24 s (none over a second, five before); the windy clip, tight: the longest pause between words 0.95 s against 1.21 s and none over a second (two before), words whole 97.9% against 97.5%, medium 99.3% against 100.0% (two words clipped by more than 15 ms); the clips on the default path and the one whose speech is within 12 dB of the noise are unchanged (all seven clips: words whole 97.6% tight, 98.8% medium).
- **One clock: the file's.** Every time in the analysis is on the clock the picture sees. silencedetect and a person's transcript (a sidecar `.srt/.vtt/.json`) already are; the speech engine's words, the 10 ms readings (`window_rms`) and the 100 ms loudness blocks count from the first decoded sample. A trimmed copy (a stream copy cut at a keyframe, a QuickTime trim) can have its audio start half a second or more after the picture (`MediaInfo.audio_start`, `media.audio_late`: the audio stream's `start_time` over the container's, 5 ms or more; the probe cache is `probe-v2.json`; a start of 0.1 s or more is said in the clip's warnings), and without this every cut of such a file landed that much early (a sidecar transcript lost the ends of its sentences, a medium cut ended 0.24 s before the sound did). So the engine's own words are moved by `Transcript.shifted` after they are made or read from the cache (the cache keeps them as the engine made them; a sidecar is not moved), the loudness map's pauses are moved when found (`_Room.offset`) and read at the words' place on the audio (`offset` in `segments.speech_stands_above_room` / `split_invented_words`), and `level_summary(..., offset)` puts the loudness blocks and the sound's end on the file's clock. `roughcut check` does the same for what it listens to (`cutcheck.audio_offset`). `tests/test_audio_clock.py`.
- **Audio levels:** speech is matched by the loudness of its words to the dialogue level, held to ±12 dB and never past −1 dBFS peaks; nat sound and music are set relative to it. Fades never reach a kept word. The music bed ducks under speech with keyframes and is back-timed so the song's own ending lands on the last frame.
- **Subscription use goes only through the Claude Code program.** `claude_code.py` runs `claude -p` (signed in by the user) and strips `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` from its environment so it can't bill the API. Never read or forward subscription OAuth credentials to the API ourselves: Anthropic's terms forbid it. `verify()` refuses an `api_key` sign-in.
- **A Claude Code call reads no file it wasn't given.** There are two doors. (1) **`@path` in the prompt**: Claude Code expands an `@path` at the start of a word itself, before any model or permission rule is asked (the file's text, a picture's pixels, a folder's listing go into the request), and transcripts, clip notes and text read off a frame are untrusted and reach the prompt, in text-only calls and picture calls alike. So every `TextPart` goes through `claude_code.defang_mentions`: an invisible zero-width space ahead of every `@` that doesn't follow an ASCII letter or digit (an address is left alone). Claude Code's "start of a word" is JavaScript whitespace, wider than Python's (a byte order mark, no-break space, U+3000, U+2028, `\r`, `\v`, `\f` all count; `str.isspace` misses the first), which is why this marks everything but a plain word instead of copying its rule. `restore_mentions` takes the mark back out of what the model answers, so a handle it copies comes back as written. Text-only calls also carry `fence_args` (`permissions.blockReadsOutsideWorkingDirectories`, Claude Code 2.1.257+; older or unreadable versions get the command line they always had) as a second lock; it is a setting among the owner's, so their own `additionalDirectories` can widen it: the marks are the boundary, the fence is for the default settings. Never `--restricted` on text-only calls: it is unchecked against a Mac's Keychain sign-in and every planner request would stand on it. (2) **The Read tool in a request with pictures.** Clip frames and the editor's reference images (untrusted: text in a picture can try to instruct the model) go to `claude -p` as files the Read tool opens. `claude_code.picture_args` is the only place that builds that call's flags: Read is the only tool, the working directory is a fresh temp folder (by its real path: Claude Code refuses a picture reached through a symlink such as macOS's `/var` -> `/private/var`) that holds only the pictures' bytes, and these refuse a read outside it and never ask: `--restricted` (file tools confined; user/project/local settings ignored, so the owner's `additionalDirectories` or `allow: Read` can't widen it), `permissions.blockReadsOutsideWorkingDirectories`, `--permission-mode dontAsk` + `--permission-prompts none`, `--disallowedTools` for the rest, and deny rules for ssh/cloud/`~/Library` secrets (a second lock, not the boundary). Never `--allowedTools Read` (it approved every path) and never `--add-dir`. The prompt says only those files may be read and that text in a picture is not an instruction. The minimum is `MIN_PICTURE_VERSION` (2.1.295): not the release the last flag arrived in (2.1.259) but the newest release that fixed these same controls, since each changelog fix is a hole in every release before it (2.1.273 macOS refusing a file the system reports under a second path, 2.1.281 a null-byte path ending the whole call, 2.1.290 a read escaping through a link changed mid-read, 2.1.295 `--tools`/`--restricted` not covering late-registered tools). An older or unreadable Claude Code has `supports_vision` False and is shown no pictures, never run unconfined: a clear error if asked anyway, graphics designed from words, `doctor` says so on its Claude Code row whatever the sign-in (`claude_code_version`, `claude_code_pictures`), and the paper edit's warnings say that the clips were not looked at or the designer got no frames. `permission_denials` in the JSON result are logged and kept in `provider.refused_reads`: a read outside the folder means something asked for it (the fence worked, the answer stands); a refusal of a picture itself fails the request (`ProviderError`, the request still counted), since Claude answered from the words alone and the visual log would cache that guess for good. `tests/test_claude_code_boundary.py` runs the installed `claude` against a loopback stand-in for the API with canary files (a `real_environment` check, so `ROUGHCUT_TESTS_REAL=1`; fake token, fake home, nothing leaves the machine): every mention form with each layer alone and both, picture reads, null-byte paths. Run it after a Claude Code update.
- **B-roll and graphics follow the same timing rule as the cut.** The planner names a segment and the exact words; `phrases` finds them in the transcript and the timeline. B-roll starts about 2 frames before its words and never shows the same footage twice within 10 s (`REPLAY_SECONDS`; software-picked in-points go to unseen parts, `_fresh_in`). Graphics never overlap, and a graphic's lead never crosses a cut, so Final Cut connects it to the clip its words are in. Designs are self-contained HTML rendered offline (network blocked) by seeking `document.getAnimations()`, SVG SMIL (`pauseAnimations`/`setCurrentTime`) and `window.seek(t)` per frame (animations `window.seek` starts later are seeked from the frame they start), so they must never depend on wall-clock timers. Each saved design ends with a `roughcut-timing` note (its seconds and word times); a design reused at other timing renders on a warped clock (`time_map`) so captions stay on their words. Every declared font is loaded before frame 0, and brand fonts are embedded, never fetched. Every frame is captured only after the page has drawn what changed (two animation frames, `graphics._DRAWN_JS`, waited on in an isolated world, `drawing_world`, so a design that replaces or shadows `requestAnimationFrame` still renders while a stuck main thread is still caught): a capture straight after a seek, or after the scale the last capture set and put back, can catch the compositor between two states with an edge a device pixel off.
- **A design can reach nothing outside its page.** It is model-written code run with scripts on, so `_render_async` renders it only through these layers, each held by a test against loopback listeners (HTTP, WebSocket, bare TCP, UDP; `tests/test_graphics_confinement.py`; a browser with none of them hears all of it): `confine_html` puts a `<meta>` content policy (`CSP`: `default-src 'none'`, `connect-src data: blob:` (a fetch or XHR of data the design carries reaches no address, and a design that decodes its own embedded data must keep working; the note for a refused load is only for addresses), inline script/style and `data:`/`blob:` pictures, fonts and media only) first in the document, after the doctype and never before it (quirks mode), looking past only whitespace and what the HTML parser takes for a comment before a doctype (well-formed comments, `<?xml ...?>`, `<!x>`, `<![CDATA[...]]>`, a nameless end tag: a `<meta>` ahead of the doctype in any of those changed the layout); `_confined_page` makes a context that is `offline`, with service workers blocked, downloads refused, `RTCPeerConnection` removed, `context.route` refusing HTTP, `context.route_web_socket` closing sockets (registered before the page exists: Playwright wraps `window.WebSocket` in an injected script, so a later registration protects nothing), and a closer for every page but its own; `_confined_launch` sends every connection (loopback included) to `DEAD_PROXY` and resolves no host name (`--host-resolver-rules=MAP * ~NOTFOUND`, so DNS prefetch leaks nothing); `SANDBOX` turns Chromium's sandbox on where it starts (the first launch tries it, proves a page draws, and decides for the process; where it can't, the same browser launches without it and the log says so once; a render never fails for it). The content policy doesn't change a design's pixels (`FONT_AND_PICTURES` is compared frame for frame with an unconfined page) or `graphic_digest`; its refusals are noted like a blocked route ("tried to load URL (blocked: ...)"); a page that navigates away is left out with that reason. Never loosen the policy for a feature (a design that wants a network asks for a bundled font or an inline asset instead), and a new way out found in the wild gets a vector in that test file first. Needs Playwright 1.48 (`route_web_socket`): `renderer_problem` (doctor, `--graphics`) refuses an older one with the pip command, and a context without the route says so once in the log.
- **Rendering never hangs and never uses processes.** One Playwright instance per thread, each running the async API under `asyncio.run` so every browser call has a deadline we enforce (`_bounded`/`_evaluate`): a stuck page never answers CDP and `page.evaluate` has no timeout. A design that freezes is left out with a note. Renders land under their final, digest-carrying name (`G01-lower-third-<digest6>.mov`) only when complete; saved designs are matched to graphics by plan `index`, never by ID.

It judges what this Python process does: any connect, send or name lookup that is not loopback (and a unix socket outside the test's folders); any program but one *named* ffmpeg, ffprobe, git or sips (wherever the file is), a Python, an installed package's own (Playwright's driver) or inside the test's folders, or one program a test names for a single call with `hermetic.allowing_programs("bash")` (the stamp tests run the app build script's bash that way; allowed inside that block only), found where Python itself would look (`env`'s PATH, else `os.defpath`), and `os.system`; any write (opening for writing, mkdir, rmdir, remove, rename, symlink, link, chmod, chown, utime, truncate, extended attributes, file flags on a Mac, `shutil` copy/rmtree/move, a SQLite database opened read-write) outside the test's folders (a `__pycache__` and `/dev` apart), also through a link inside them, and a call relative to a held directory is judged by that directory where the platform says which (Linux `/proc`, macOS `F_GETPATH`); any read in the real home folder (opening a file, listing a folder, a SQLite database opened read-only), also through a link (the repository, the Python installation and Playwright's browsers apart). *What it does not see, and so does not claim:* `stat` and `exists`; `os.open(..., dir_fd=...)`, `os.mkfifo` and `os.mknod` (Python raises no event for them); `ctypes` and other native code; `os.spawn*` (refused only inside the process it forks, which exits 127, so the test is not failed); what a program it lets run does (ffmpeg, git, sips, bash for the stamp tests, a Python child, Chromium); code that runs when a test file is imported or collected (the `skipif`s that start Chromium or look for `claude` are outside the sandbox: keep such code to looking); other threads once a test has ended; with `HOME=/` the read guard is off (the report header says so).
