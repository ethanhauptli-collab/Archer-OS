# roughcut: notes for Claude Code

Footage folder → transcripts → LLM edit plan → frame-accurate timeline → FCPXML for Final Cut Pro. A Python CLI (the engine) plus a SwiftUI Mac app in `mac/` that drives it. The owner edits Venture Orange County promos and a personal YouTube channel (Save the Kid) in Final Cut Pro 11 on an Apple Silicon Mac; this tool produces the first pass they refine there.

| `roughcut/prompts.py` | Planner/vision/moments prompts; media block rendered deterministically for prompt caching (a Studio song's tags, notes, provider and favorite on its own line, capped: `library_line`), showing each line's kept length at the run's style (Auto pacing: at medium, and the brief says what tight and loose make of them, `pacing_choice`); with graphics off the brief tells the planner the cut has none |

| `roughcut/phrases.py` | Find planner-named words in the transcript and the cut (shared by B-roll and graphics placement) |

| `roughcut/paths.py`, `update.py` | Rejoin unquoted paths with spaces; `roughcut update` |
| `roughcut/progress.py` | `--progress-json` JSON-lines events for the Mac app; heartbeat and stall dump |

## Invariants: don't break these

- **The model never produces timestamps for speech.** It picks segment IDs and names words; `timeline.py` computes cuts. Anything the model returns goes through `plan.normalize()`, which drops unknown IDs with a warning and never raises. No line plays twice: a repeat from another read or export is dropped and recorded as an alternate, and a take the plan's own `alternates` list among a line's others is dropped when the chosen take is in the cut, else replaced by it (heuristic/stringout plans are exempt so `render` reproduces them). Only a real retake counts (`duplicates.another_read`: at least half the line's content words, however reworded, the same line, or one inside the other): a flub or another line listed there is left where it is and never named as an alternate. The editor wins: a take `--keep` names is never dropped or replaced (when it names two takes of one line, the chosen one plays and the other stays an alternate, with a warning, and `enforce` doesn't call it missing), an avoided chosen take never goes in place of another (the other take in the cut plays and becomes chosen), and a revision that plays another take where the last version played the chosen one keeps the swap; `revise` saves the reconciled alternates in `plan.json`'s raw plan so re-cuts play the same takes, and `render` and `revise` read an older plan.json's raw alternates as its saved plan played them (`plan.as_played`).
- **No floats in FCPXML.** All times are `Fraction`s; spine `offset`/`duration` are whole multiples of the sequence `frameDuration`; source in-points snap to the source's own frame grid; audio fades are whole samples.
- **FCPXML coordinates:** spine `offset` = timeline time. Spine `start` = asset timecode origin + source in. Connected clips, markers and volume keyframes live in the **parent's (or the clip's own) source time** (`start + (frame − offset) × frameDuration`). Stills use `<video>` with a `3600s` origin; browser stills are `<clip><video duration="0s"/></clip>`. Audio-only clips carry `format` = `FFVideoFormatRateUndefined`. Every clip names its own `format` when it differs from what it would inherit (the sequence's on the spine, the parent's when connected; browser clips always), and a clip at another frame rate gets `<conform-rate scaleEnabled="0" srcFrameRate=…/>` so it plays at real speed, as Final Cut writes them. Never put `adjust-volume` on `<video>`. All of this is checked against Apple's DTD and against real Final Cut 10.7/11 exports in `tests/fixtures/fcp_exports/` (`tests/test_fcp_exports.py`; `check_invariants` enforces the format rule).
- Tests validate every generated FCPXML against `tests/fixtures/FCPXMLv1_10.dtd` (Apple's DTD) and check timing invariants (`tests/test_end_to_end.py::check_invariants`). Keep both passing.
- **The app ↔ CLI contract is `--progress-json`** (one JSON object per stdout line: `stage` / `log` / `done` / `error`; stages `scan probe silence transcribe vision plan cut graphics write`, only ever moving forward; `error` is last and may carry `resume` (after a saved plan, also on SIGTERM/SIGHUP and unexpected errors) and `kind` (`usage_limit`, `cancelled`)), `done.result` = `pipeline.result_summary` (keys may be added, never removed or renamed; `cut` holds the version's style, format, fillers and stringout so the app's Re-cut starts from them), `roughcut doctor --json` and `roughcut preset list --json`. `mac/Tests/RoughcutKitTests/Fixtures/progress-sample.jsonl` (a build) and `progress-revise-sample.jsonl` (a revision, with its `changes`) are real output; the Swift tests decode them and `tests/test_progress.py` fails if the Python side drifts. Change both sides together and regenerate the fixture.
- **A rejected API key or a used-up plan/credit stops the run** (`ProviderAuthError`, `ProviderLimitError`): `build` calls `provider.verify()` before any analysis, and both are fatal during vision/planning. Only other model failures may fall back to the stringout, and that fallback is announced at the top of the report and in the CLI output.
- **The plan is saved before anything that can still fail** (cutting, graphics): `analysis.json` + `plan.json` (with `analysis_digest` and the run's settings) are written right after planning, so `roughcut render` can always finish without the model. `render` refuses a plan whose digest doesn't match, and takes every cut setting it isn't given from the saved run (in Terminal and from the app alike). `revise` writes `graphics.json` (carried designs, new ones without html) as soon as its plan is saved; `render --design-missing` designs only graphics without html, with the run's own model, never re-planning. Outputs are numbered versions written atomically (temp file + rename); earlier versions are copied to `history/` (last 5). Never move files at run start, and never delete a rendered graphics clip any written version used: Final Cut reads imported media in place.
- **Dead air is cut by the silence map, not by word times.** mlx-whisper's word times are contiguous, and the word next to a pause is stretched over it. `timeline._cut_silences` runs after merging and removes every silence longer than the style's `max_gap` (or `max(1 s, 2×max_gap)` for a finished promo over a music bed, `Clip.bed == "music"`) that has sound on both sides inside a kept piece. It never cuts a "silence" that holds a whole transcribed word. A pause split by a quiet breath or click (≤ 0.4 s, ≥ 12 dB under the speech, no word starting in it and no word whose only sound is in it, `pauses.word_in_pause`) counts as one pause: on camera it goes in one edit, breath included (the one bounded exception to "never removes sound"); in narration the breath stays. Words are dropped as Whisper inventions only by the standard −35 dB map, never by a raised one. `tests/test_dead_air.py` covers the 10-14 s gap case and music-bed promos.
- **Audio levels:** speech is matched by the loudness of its words to the dialogue level, held to ±12 dB and never past −1 dBFS peaks; nat sound and music are set relative to it. Fades never reach a kept word. The music bed ducks under speech with keyframes and is back-timed so the song's own ending lands on the last frame.
- **Subscription use goes only through the Claude Code program.** `claude_code.py` runs `claude -p` (signed in by the user) and strips `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` from its environment so it can't bill the API. Never read or forward subscription OAuth credentials to the API ourselves: Anthropic's terms forbid it. `verify()` refuses an `api_key` sign-in.
- **B-roll and graphics follow the same timing rule as the cut.** The planner names a segment and the exact words; `phrases` finds them in the transcript and the timeline. B-roll starts about 2 frames before its words and never shows the same footage twice within 10 s (`REPLAY_SECONDS`; software-picked in-points go to unseen parts, `_fresh_in`). Graphics never overlap, and a graphic's lead never crosses a cut, so Final Cut connects it to the clip its words are in. Designs are self-contained HTML rendered offline (network blocked) by seeking `document.getAnimations()`, SVG SMIL (`pauseAnimations`/`setCurrentTime`) and `window.seek(t)` per frame (animations `window.seek` starts later are seeked from the frame they start), so they must never depend on wall-clock timers. Each saved design ends with a `roughcut-timing` note (its seconds and word times); a design reused at other timing renders on a warped clock (`time_map`) so captions stay on their words. Every declared font is loaded before frame 0, and brand fonts are embedded, never fetched. Every frame is captured only after the page has drawn what changed (two animation frames, `graphics._DRAWN_JS`, waited on in an isolated world, `drawing_world`, so a design that replaces or shadows `requestAnimationFrame` still renders while a stuck main thread is still caught): a capture straight after a seek, or after the scale the last capture set and put back, can catch the compositor between two states with an edge a device pixel off.
- **Rendering never hangs and never uses processes.** One Playwright instance per thread, each running the async API under `asyncio.run` so every browser call has a deadline we enforce (`_bounded`/`_evaluate`): a stuck page never answers CDP and `page.evaluate` has no timeout. A design that freezes is left out with a note. Renders land under their final, digest-carrying name (`G01-lower-third-<digest6>.mov`) only when complete; saved designs are matched to graphics by plan `index`, never by ID.
- **Reference images are the editor's private pictures** and may show other people's brands: they reach only the graphics design requests (like approved designs and the logo), as `ImagePart`s after one intro text, never the planner, the vision step, `graphics.json`'s style, a log or the report beyond their stored file names (a picture left out is named in its warning by file name, never its folder). The design request goes to the model that designs the graphics, so the pictures do leave the Mac, as clip frames do (the READMEs and the app's caption say so). Settings (`graphics_refs`) hold the stored names, relative to the output folder (`stored_names` rejects anything else), never the original paths or bytes, so a moved original changes nothing for `render --design-missing` or a later revision; pictures given to `revise` replace the saved ones (the old files stay in `graphics/references/`). All file work on them is bounded, a bad one is a warning, never a failed run, a model that can't look at images is told once and sent none, a request a model turns down for them is sent once more without them, and one that fails some other way (a busy model, a timeout) is sent once more with them and goes without only if that fails too (a rejected key or a used-up plan is never sent again), said in a warning. The designer's house style (saved in `graphics.json`) is what keeps the look without them. A build without them sends exactly the design requests it always did. The Mac app only decodes a picture to draw its thumbnail and keeps a pasted or dropped bitmap, as it came (a TIFF off the pasteboard as a PNG; the same bytes are the same file; none over 40 MB, none when the list is full), in `~/Library/Application Support/Roughcut/References/` (removed after 30 days once no saved list uses it); it passes paths to the CLI as `--graphics-ref=<path>` (only with graphics on) and never uploads or logs a picture; the Revise box's pictures and Redesign switch count only for a cut that has graphics.
- **What the "What changed" list says is what happened** (`revise.change_items`, the one list behind the paper edit, the CLI and `done.result.changes`): it compares what a viewer would see (lines, B-roll with where each shot starts, a mid-cut song's start, graphics with their length and design inputs, every render setting, the sound-effect amount and sounds and how many accents each version has, the song a cut plays), puts the sentence that nothing differs, with what to try, first (the app highlights it), and is built again once the graphics are made so a graphic that never came back is not called redesigned or new. A re-cut is "the same cut" only when every setting matches. A change to the paper edit's Venture Studio section (credits, what Studio matched) is not a change to the cut and gets no line. A revision keeps every graphic's design unless its design key changed (`plan.spec_key`: kind, line, words, text, subtext, direction); every graphic is designed again only for `--redesign-graphics`, new `--graphics-ref` pictures or the planner's `redesign_graphics` = yes. The notes of the revisions that asked for another look are saved (`graphics_direction`, the latest ten) and go to the designer with later redesigns and with `render --design-missing`; pictures or the flag start the look over, notes alone change the look the graphics have now (`<current_look>`). A graphic whose new design never comes back keeps its earlier one when it says the same words, except after the usage limit (those wait for `--design-missing`, in the look the notes asked for).
- **Presets never invent brand colors.** Venture OC's palette and fonts are the ones ventureoc.com uses; anything else is the owner's to set. Approved designs and the logo reach only the design request, never the planner or `graphics.json`'s style.
- **An audio-only storyline (narration) never plays over black**: `timeline._fill_picture` covers any gap the plan left, matching narration words to clip names/visual tags, preferring moving footage, never repeating a still while video can cover, never leaving a sub-0.5 s sliver, never replaying the shot on screen; it goes round again (up to 4 rounds) to cover anything a moved still uncovers.
- **Venture Studio is read-only.** `roughcut/studio.py` is the only code that looks inside Studio's data folder (`~/Library/Application Support/com.hauptli.venturestudio`, or `$ROUGHCUT_STUDIO_DIR`). Nothing there is ever opened with SQLite (not the live catalog, its sidecars, the other databases, or a snapshot in place), written, renamed or locked, and `catalog.worker-lock` is never opened: Studio's restore needs it. Catalog data comes only from a byte copy of Studio's newest daily snapshot (`backups/<id>.sqlite` + its `<id>.json` manifest) streamed into Roughcut's own cache (`Options.cache_dir` or `default_cache_dir()`, under `venture-studio/`) and checked against the manifest's size and SHA-256 and a rollback-journal header (a link, FIFO, a snapshot with `-wal`/`-shm`/`-journal` beside it, or a mismatch is skipped with a reason, and a skipped newest snapshot, the "Before catalog restore" copy, an imported or an old one is reported), then opened only as that copy through `Path.as_uri()` with `mode=ro&immutable=1`; or from a kit JSON the owner exported (format 1, `project.assets`). `studio.py` creates nothing under a library root, and neither does the Terminal offer (its folder is checked, links followed, to be outside every library); an output folder that is inside a library (the default next to footage there, from the app, `-o`, an existing project, a declined offer, `--no-menu` or a non-interactive run) is still written there, with the guard's warning. Library files a cut uses are only read and referenced in place. Every Studio problem is a reason string (`StudioUnavailable`), never a failed run (the exceptions: a song asked for by its Studio ID, and a collection typed for `--sfx-from`, before the output folder exists), and a Mac without Studio hears nothing of it (doctor says "not installed"; the app shows no row). The output guard warns (log and the paper edit's warnings) when the output folder is inside a library (`inside_library`: whole folder names, exactly, then ignoring Unicode form and case; a share macOS mounted as `/Volumes/<name>-1` counts as `/Volumes/<name>`; a catalog row without an absolute path holds nothing); only an interactive Terminal build with the default folder, no `--progress-json` and no `--no-menu` asks, offering `~/Movies/Roughcut/<library>/<path below the root>_roughcut` (itself checked, links followed, to be outside every library). `doctor --json`'s `venture_studio` key is add-only, never changes doctor's exit code, and `--offline` skips the online check. **The paper edit's Venture Studio section** (`studio.match_media`) predicts Studio's Project history review by pure string comparison, never a stat of a media path: each path the FCPXML's projects use, songs, sound effects and footage alike (Studio's walk: audition picks, disabled clips, compound clips, time windows, its limits and project-name rule; media-rep file URLs decoded as Studio does) against every catalog row at `catalog_path` (missing rows too; a row Studio refuses makes its review refuse every file) and prepared outputs (`project_history_items` of `kind='prepared'` events, when the copy has them); matched items count once each and are credited with their provider and license, a path with two items is ambiguous, and an unmatched path is a near miss (case, Unicode form, `/Volumes/<name>-N`), not in the snapshot yet (under a library root), not in a kit (kit only), outside, or Roughcut's own render; never "not in Studio". It's saved as `studio_sources` in plan.json (revise carries it over) so render and revise rebuild it without Studio; a path the saved map lacks reads "not checked" (one under the output folder, a graphic's render a re-cut renamed, is Roughcut's own: "render"). No section without Studio or when nothing in the cut is Studio's; one line when Studio is installed but unreadable. Nothing is added to the output folder for it. **Music from Studio**: `studio music` lists standalone audio only (`STANDALONE_AUDIO`: present, browse-visible, no template package or resource), with Studio's length or "?" (no probing), and prints a JSON array, never an object. `--music studio:ID` resolves in `cli` before the output folder exists and may stop the run (unknown id, unreadable snapshot, offline or stalled share, all within `FILE_SECONDS`); `--music-from` and a user preset's `music_from` are soft (a warning, never a stopped run), add candidates after every typed `--music` (`Clip.music_order` keeps the typed one first), and built-in presets never set it. A song given more than once (as `studio:ID` and as its path) is one clip. Every touch of a kit file (`is_kit_file`, `load_kit`: `--music-from`, `studio music --kit`, the paper edit) and of a Studio song's file (existence, probe, silence and loudness, `missing_media`, the FCPXML's src, which is its path as Studio has it, never resolved) has a deadline (`textio.bounded`), and a song whose share stalls is dropped with a warning (a collection whose files aren't reachable is told apart from one with no songs); the app's Music bed never waits on a `/Volumes` path (the CLI checks it). Studio is private: no copy of its source, schema or docs in this public repo (tests build a fake catalog from SQL written in the test, with only the tables and columns Roughcut reads), and none of the owner's private details (network shares, library folder names, vendors, catalog counts) in code, comments, tests or docs.
- **Sound-effect accents land on the cut's own frames.** The planner only says how many (`sfx`: none / soft / full / unspecified, read from the brief or a revision's notes like pacing; unspecified or no model: soft). `accents.py` places them: a whoosh at each section change after the first; a pop on each lower third and a hit on each title card or stat attached to the cut (from `tl.connected` after graphics are made, never `graphics.make`'s placed list, so one that never rendered gets none); with full also a whoosh on the first B-roll cut of each 1.5 s+ stretch without speech and a riser ending on the last section's first frame when that's 20 s+ in. About 2 s apart; a hit beats a pop, a section whoosh, a montage whoosh, a riser (an accent on a riser's own frame doesn't compete with it). None in the stringout; a no-AI cut gets at most soft. The hit (loudest 50 ms; a riser's end) lands in the event frame; an accent is whole frames of its file (never reading past it), trimmed at the cut's ends with whole-sample de-click fades only there; the same file never within `REPLAY_SECONDS`; each class takes its sounds in turn by path. Connected audio below every music lane, `audioRole="effects.SFX"`, rate-undefined format, and always an `adjust-volume`: `SFX_DB` under the dialogue level (6 dB lower where a kept word sounds under it; a sound too short to measure levelled by its peak), never past -1 dBFS, a fixed gain with levels as recorded; placed again after graphics, with its own `tl.levels` rows. The pool is audio-only files in `AUDIO_EXTS` up to 8 s with a class word; every touch of a sound file (stat, ffprobe, ffmpeg, a kit file, `missing_media`, finding where `--sfx` paths really are) runs under `textio.bounded`, a folder listing under `sfx.list_folder`'s silence watch (slow but answering is read to the end; silent keeps the folders it finished), and a share that's offline or stalls drops its sounds with a warning, never failing or hanging a run; only a `--sfx-from` name typed for a build that Studio's catalog lacks (or an unreadable kit file) stops it, before its folder is made. A pool the time limit (`POOL_SECONDS`) left partly unread keeps what it read: a re-cut or revision places the same sounds again and its note says that only a new build or new `--sfx`/`--sfx-from` reads the rest. The resolved pool is saved in plan.json's settings (outside `analysis_digest`: sound clips go only into an in-memory analysis copy), so `render` and `revise` place the same sounds without reading the share or Studio; only used sounds reach the event browser. Sound effects are never footage (an `--sfx` folder or file inside a footage folder, even one reached through a link, is left out of its scan: `pipeline.footage_files`). The accents are placed again once graphics are attached, and the paper edit's notes and the missing-media check use that final placement. The Mac app sends only names typed in its form that session as `--sfx-from` (strict); remembered and preset names go as `--preset-sfx-from` (a warning). A Studio sound's file is named in the FCPXML as Studio has it (never resolved), so the paper edit's Venture Studio section counts and credits it like a song. Without a pool nothing changes, byte for byte; built-in presets never carry sounds.
- **Long waits are visible.** Waits on a model or `claude -p` are wrapped in `progress.doing(..., external=True)`; the heartbeat logs "still working" every minute, and only a stall outside those waits gets a stack dump in `roughcut.log`.
- Claude calls use `claude-opus-5-5` by default (`claude-sonnet-5-5` via the Terminal model menu, `--model sonnet`, or the app's menu; `anthropic_provider.resolve_model` turns any spelling like `Claude-Sonnet.5.5` into the id; same request shape works for both), adaptive thinking (implicit on this model), `output_config.effort`, streaming, and structured outputs via `output_config.format`. Don't add `thinking: {type: "disabled"}` or `budget_tokens` (400 on this model) or forced `tool_choice`.

## Commands

```bash
.venv/bin/python -m pytest -q                       # all tests (needs ffmpeg; graphics tests need Playwright Chromium)
roughcut build <folder> --preset venture-oc -c "brief"
roughcut build <folder> --provider none             # silence-only, no API
roughcut build <folder> --sfx FOLDER --sfx-from "Collection"   # sound-effect accents (a folder, a Studio collection)
roughcut revise <out_dir> "notes"                   # re-plan from notes as a new version
roughcut render <out_dir> --style tight             # rebuild from saved plan, no model
roughcut render <out_dir> --design-missing          # design graphics a stopped run never designed
roughcut build <folder> --graphics --graphics-ref look.png   # reference images for the graphics' look (up to 8)
roughcut revise <out_dir> "bolder" --redesign-graphics      # every graphic designed again (also: --graphics-ref IMAGE)
roughcut preset list | show | save | remove
roughcut update                                     # git pull + reinstall when needed
roughcut doctor                                     # ffmpeg / transcriber / graphics / Claude Code / API key / Venture Studio
roughcut studio status [--json] [--where DIR]       # what Roughcut can read from Venture Studio (read only)
roughcut studio music [WORDS] [--collection NAME] [--json]   # Studio audio a music bed can use
roughcut build <folder> --music studio:12           # a Studio song; --music-from "<collection>" offers several

cd mac && swift test                                # RoughcutKit tests (needs Xcode)
mac/scripts/build-app.sh --install                  # build Roughcut.app into /Applications
```

CI (`.github/workflows/ci.yml`) runs on every push: the Python suite on Linux; the Python suite plus a real-speech mlx-whisper smoke test (`.github/scripts/mac-engine-smoke.sh`: preset, `--music`, versions, vertical re-cut, DTD) on an Apple Silicon Mac; and `swift build`, `swift test`, `build-app.sh` and a launch check for the Mac app on Xcode 16.4.
